# SPEC — Bank Credit Policy Agent Demo (Gemini)

## §G GOAL

Demo: credit officer in Google Chat asks an ADK Python agent on Agent Runtime. `InteractiveAgent` holds `PolicyPack` (12 Contoso Demo Bank Markdown policies, one GCS read of `credit-policies/policy-pack.md` per cache fill) and answers with citations. Status question by `application_id` or `customer_name` calls `lookup_application` once and judges `accepted` or `rejected` or `missing-data` from that application hit plus the pack. Policy question answers from the pack with zero searches. Not a production origination system. Same use case as kborovik/azure-ai-foundry. Document generation unchanged: facts.yaml + Jinja policies, Gemini JSON filings from the same application prompts.

## §C CONSTRAINTS

- demo: no origination system-of-record; no real borrower PII; no real bank IP; no production credit decisioning
- stack: Google ADK Python on Agent Runtime; officer client = Google Chat; one Agent Search data store; GCS holds `credit-policies/policy-pack.md`; officer reads that object once per cache fill; upload does not import
